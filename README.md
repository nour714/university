# 🎓 بوابة المقررات الأكاديمية | كلية الذكاء الاصطناعي
> **Faculty of Artificial Intelligence — Academic Course Portal**  
> منصة أكاديمية تفاعلية حديثة، فائقة السرعة، مصممة لاستيعاب حركة الطلاب الضخمة بكفاءة واستهلاك أدنى للموارد مع تجربة مستخدم استثنائية على كافة الأجهزة (Mobile-First).

---

## 🌟 نظرة عامة (Overview)

بوابة إلكترونية متطورة مخصصة لطلاب وأعضاء هيئة التدريس بكلية الذكاء الاصطناعي، تتيح استعراض المقررات الدراسية، تحميل المحاضرات والمذكرات بصيغة PDF، مشاهدة الفيديوهات التعليمية، تصفح المخططات المعمارية والخرائط الذهنية، والوصول إلى الروابط البرمجية ومستودعات GitHub المعتمدة.

تم بناء المنصة وفق أحدث معايير هندسة البرمجيات:
- ⚡ **أداء فائق و سرعة استجابة لحظية**: بالاعتماد على خوادم Edge وتوليد الصفحات الثابتة (SSG) ومكونات الخادم (Server Components).
- 📱 **تصميم متجاوب بالكامل (Mobile-First)**: تجربة تصفح مثالية وسلسة على مختلف مقاسات الهواتف الذكية والأجهزة اللوحية والشاشات العريضة.
- 🎨 **هوية بصرية أكاديمية راقية**: ألوان كحلية ملكية (`#172554`)، لمسات زرقاء ديناميكية (`#2563EB`)، وشعار ذهبي مميز يعكس فخامة الصرح الجامعي.
- ♿ **دعم كامل للغة العربية (RTL)**: استخدام خط **Cairo** العربي الجذاب، واعتماد الخصائص المنطقية للـ CSS (`margin-inline`, `padding-inline`) ومطابقة معايير إمكانية الوصول **WCAG 2.1 AA**.

## 🚀 المميزات الرئيسية (Key Features)

### 1. الصفحة الرئيسية ولوحة التحكم (`/`)
- **بانر ترحيبي عائم**: يعرض بيانات الطالب الأكاديمية، العام الدراسي الحالي، والقسم العلمي.
- **شبكة إحصائيات بنتو (Bento Stats Grid)**: عرض فوري لـ:
  - المعدل التراكمي (GPA) مع التقدير الجامعي.
  - عدد الساعات المسجلة المعتمدة.
  - المستوى الدراسي الحالي وحالة القيد.
  - عدد المقررات النشطة لهذا الفصل.
- **بطاقة وصول سريعة**: للانتقال المباشر لمكتبة المقررات الدراسية.

### 2. مكتبة المقررات الأكاديمية (`/courses`)
- **بحث فوري وسريع**: تصفية المقررات في الوقت الفعلي حسب اسم المادة، كود المقرر، اسم الدكتور، أو القسم.
- **بطاقات مقررات أنيقة**: توضح كود المقرر، المستوى الدراسي، الفصل، القسم، اسم أستاذ المادة، وإجمالي المحتويات الأكاديمية مع أزرار لمس مريحة للهواتف (بارتفاع 44px كحد أدنى).

### 3. صفحة تفاصيل وتصفح محتويات المقرر (`/courses/[id]`)
- **رأس صفحة كحلي متدرج**: يضم كود المادة، عنوان المقرر، اسم أستاذ المادة، وزر عودة سريع للمكتبة بلون متباين.
- **متصفح محتويات تفاعلي متعدد التبويبات**:
  - 📄 **جميع المحتويات (All)**: استعراض شامل لكل ما يخص المادة.
  - 📚 **المحاضرات والملفات (Files)**: مذكرات وسلايدات وشيتات بصيغة PDF.
  - 🎥 **الفيديوهات (Videos)**: تسجيلات القاعات الذكية وشروحات المعامل مع إيضاح مدة كل فيديو.
  - 📊 **المخططات والصور (Images)**: الخرائط الذهنية والمعماريات الرقمية بدقة عالية.
  - 🔗 **الروابط البرمجية (Links)**: دفاتر Google Colab ومستودعات GitHub والمراجع الرسمية.
- **عرض مزدوج ذكي**:
  - **عرض الجدول المنظم (Desktop Table)**: للشاشات الكبيرة بنمط سحابي أنيق مستوحى من Google Drive.
  - **عرض البطاقات السريعة (Mobile Cards)**: للهواتف الذكية مع إمكانية "العرض المباشر" أو "تنزيل الملف" بنقرة واحدة.

### 4. نظام الملاحة الهجين (Navigation System)
- **شريط علوي عائم (Floating Pill Header)**: يحتوي على عنوان الكلية، العام الأكاديمي، وأيقونة الملف الشخصي للطالب الدائرية النظيفة.
- **شريط جانبي للشاشات الكبيرة (Desktop Sidebar Dock)**: كبسولة ملاحة عائمة كحلية تضم شعار الكلية الذهبي، زر مكتبة المقررات، إمكانية التمدد والطي، وأزرار الاختصارات الإضافية.
- **شريط سفلي للموبايل (Mobile Bottom Dock)**: شريط عائم منحني الحواف في أسفل الشاشة، يسهل الوصول لجميع الأقسام الرئيسية بإبهام اليد الواحدة.

## 💻 التشغيل والتثبيت (Getting Started)

### 1. المتطلبات الأساسية
- تثبيت بيئة **Node.js** (الإصدار 18 أو أحدث).
- مدير الحزم `npm` أو `pnpm` أو `yarn`.

### 2. تثبيت الحزم
```bash
npm install
```

### 3. تشغيل خادم التطوير (Development Server)
تم ضبط المشروع مسبقاً ليعمل على المنفذ المخصص **`5500`**:
```bash
npm run dev
```

- **محلياً على جهازك**: [http://localhost:5500](http://localhost:5500)
- **من هاتفك عبر شبكة الواي فاي المحلية**: `http://<YOUR_LOCAL_IP>:5500` (مثل `http://192.168.1.4:5500`)

### 4. إنشاء النسخة الإنتاجية (Production Build)
```bash
npm run build
```

### 5. تشغيل خادم الإنتاج (Production Server)
```bash
npm run start
```

## 🔒 معايير الأمان والهندسة المطبقة (Engineering & Security Standards)

> [!NOTE]
> **طبيعة النموذج الأولي (Frontend Prototype):** هذا المشروع حالياً نموذج أولي لواجهة المستخدم (Frontend-only Prototype). لا توجد قاعدة بيانات، ولا خادم مصادقة، ولا خدمات خارجية مرتبطة. عمليات تسجيل الدخول، وتغيير كلمة المرور، ورفع تذاكر الدعم الفني، وتفعيل أكواد المقررات هي عمليات **محاكاة تفاعلية (Simulated)** عبر المتصفح و`localStorage`.

- **حماية مفاتيح الإجابات والتصحيح على الخادم (Server-Only Exam Grading)**:
  - عزل مفاتيح إجابات الامتحانات (`correctOptionId`) وشروحات الأسئلة (`explanation`) داخل ملفات معزولة تماماً بحزمة `server-only` (`data/exam-keys.server.ts`) لضمان عدم تسريبها نهائياً إلى كود المتصفح أو حزم الـ JavaScript أو ردود الـ RSC.
  - تصحيح إجابات الامتحانات يتم حصرياً عبر Server Action آمنة (`gradeExam` في `app/exams/actions.ts`) مع التحقق الصارم من المدخلات بواسطة Zod، وإرجاع نتيجة الدرجة والنسبة المئوية فقط بدون كشف الإجابات النموذجية.
  - ضبط جلسات الامتحانات والعد التنازلي محلياً عبر مستودع محصّن (`lib/repos/examSessionRepo.ts`) يمنع التلاعب بالوقت أو إعادة ضبط المؤقت بعد الانتهاء.
- **حظر روبوتات الفهرسة وتأمين الترويسات (Robots & Header Hardening)**:
  - تعطيل ترويسة كشف التقنية `poweredByHeader: false` في `next.config.ts`.
  - إضافة توجيهات حظر الفهرسة لكافة عناكب البحث عبر `robots: { index: false, follow: false }` في البيانات الوصفية وملف `app/robots.ts` لحماية خصوصية البوابة الأكاديمية.
- **ترويسات الأمان الصارمة (HTTP Security Headers)**: تفعيل ترويسات الحماية المتقدمة على كافة المسارات عبر `next.config.ts`:
  - `X-Content-Type-Options: nosniff` لمنع هجمات تخمين نوع الملفات (MIME-type sniffing).
  - `X-Frame-Options: DENY` لمنع هجمات Clickjacking وتضمين المنصة داخل إطارات خارجية.
  - `Referrer-Policy: strict-origin-when-cross-origin` لحماية خصوصية مسارات التنقل.
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()` لتعطيل الحساسات والصلاحيات الحساسة غير المستخدمة.
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` لفرض بروتوكول HTTPS المشفر دائماً.
  - `Content-Security-Policy-Report-Only`: سياسة أمان محتوى دقيقة في **وضع المراقبة (Report-Only)**؛ تراقب وترصد أي انتهاكات محتملة في سجلات المتصفح بدلاً من الحظر المفاجئ، تمهيداً لتفعيلها الصارم عند اكتمال الربط بالخادم.
- **تعقيم الروابط ومسارات التنقل الداخلي (Navigation & URL Sanitization)**:
  - التحقق الدقيق من سلامة المسارات الداخلية عبر الدالة `safeInternalPath` لمنع هجمات إعادة التوجيه المفتوح (Open Redirect) وبروتوكولات `javascript:` والمسارات النسبية (`//evil.com`) مع العودة الآمنة إلى `/courses`.
  - التحقق الصارم من روابط المقررات والتنزيلات الخارجية عبر `isSafeExternalUrl` وحصرها في بروتوكول `https:` فقط، مع تعطيل أي رابط مشبوه (`aria-disabled`) دون تشويه هيكل الصفحة.
- **التحقق من البيانات والتخزين المحلي عبر Zod (Schema Validation)**:
  - مطابقة وتدقيق كافة البيانات المخزنة محلياً ضد مخططات Zod الصارمة (`StudentCodeListSchema` و `AcademicNotificationListSchema` و `ExamSessionStorageSchema`).
  - تحديد قيود حماية صارمة: حد أقصى 200 عنصر للقوائم وحد أقصى 500 حرف لأي حقل نصي.
  - التسامح مع الأخطاء واستعادة الحالة الآمنة تلقائياً: في حال العبث ببيانات `localStorage` أو تلفها، يتم حذف المفتاح الفاسد تلقائياً والرجوع للقيم الافتراضية بأمان ومنع انهيار التطبيق.
- **عزل طبقة الوصول للبيانات وتطهير الجلسة عند الخروج (Decoupled Repo & Session Clean)**:
  - فصل منطق القراءة والحفظ داخل مستودعات مستقلة (`codesRepo`, `notificationsRepo`, `examSessionRepo`).
  - تنظيف وحذف كافة البيانات المحلية الحساسة (`academic_*`) وتصفير ذاكرة الإشعارات اللحظية فور تسجيل الخروج (`clearSession` في `sessionRepo.ts`) لمنع اطلاع المستخدمين التاليين على الأجهزة المشتركة.
- **توليد المعرفات والنسخ الآمن**:
  - استخدام `crypto.randomUUID()` لتوليد المعرفات الفريدة مع بديل احتياطي موثوق.
  - حماية عمليات النسخ إلى الحافظة عبر `navigator.clipboard.writeText` بمعالجة الأخطاء غير المتزامنة.

## 🗺️ خارطة طريق الأمان للإنتاج (Backend Security Roadmap)
المتطلبات الإلزامية التي يجب أن يطبقها الخادم الحقيقي (Backend) عند نقل المشروع لمرحلة الإنتاج:
1. **المصادقة وإدارة الجلسات الحقيقية (Real Authentication & Session Management)**:
   - ربط المنصة بنظام الدخول الموحد للجامعة (SSO / OAuth 2.0 / SAML).
   - استخدام ملفات تعريف ارتباط آمنة ومشفرة ومحمية من القراءة عبر الجافاسكريبت (`HttpOnly`, `Secure`, `SameSite=Strict`).
   - دعم إبطال التوكنات (JWT revocation) وإنهاء الجلسات فورياً من جانب الخادم (Server-side Session Revocation).
2. **إدارة وقت وجلسات الاختبارات على الخادم (Server-Side Exam Sessions & Timers)**:
   - تحديد موعد بدء الامتحان، والحد الزمني، ومهلة التسليم رسمياً على الخادم بدلاً من الاعتماد على ساعة المتصفح و`localStorage`.
   - تسجيل عدد محاولات دخول كل طالب للاختبار (Per-Student Exam Attempts) وقفل المحاولة لمنع استئنافها بعد انتهاء الوقت أو تجاوز المحاولات المصرحة.
3. **التحقق من أكواد الوصول على الخادم (Server-Side Code Redemption)**:
   - نقل عملية التحقق من أكواد المقررات وتفعيلها إلى نقطة نهاية خادم مشفرة (`POST /api/codes/redeem`) مع التحقق الذري (Atomic Transactions)، ومنع استخدام الكود لأكثر من طالب واحد، وحفظ ملكية المادة في قاعدة البيانات.
4. **الروابط الموقعة للملفات الأكاديمية (Signed URLs for Materials)**:
   - توليد روابط مؤقتة وموقعة رقمياً (Cryptographically Signed Short-Lived URLs) لتنزيل المحاضرات واستعراض مقاطع الفيديو عبر التخزين السحابي المحمي (S3 / Cloud Storage) لمنع مشاركة الروابط مع غير المصرح لهم.
5. **تحديد معدل الطلبات وحماية واجهات برمجة التطبيقات (Rate Limiting & Anti-Abuse)**:
   - تطبيق آليات حظر الطلبات المتكررة والحماية من هجمات القوة الغاشمة (Brute Force / Credential Stuffing) على واجهات تسجيل الدخول، وتفعيل الأكواد، وتقديم الاختبارات.
6. **تفعيل سياسة CSP الإلزامية بالأرقام العشوائية (Strict CSP with Nonces)**:
   - ترقية سياسة أمان المحتوى من وضع المراقبة (`Content-Security-Policy-Report-Only`) إلى وضع الفرض الصارم (`Content-Security-Policy`) مع استخدام `nonce` ديناميكي للسكربتات المضمنة بدلاً من `'unsafe-inline'`.
